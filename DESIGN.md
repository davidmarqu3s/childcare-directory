## Problem Statement

Portugal has ~5,900 crèches and jardins de infância, but there is no single place for parents to discover what's available near them. Parents rely on word-of-mouth and fragmented sources. The information asymmetry is real: public, IPSS, and private options exist in every neighbourhood, but a parent in Alvalade doesn't know which 47 options are within 2km of them — or how they differ.

This product makes Portugal's childcare infrastructure visible and legible for the first time.

## What Makes This Cool

The EUREKA: Everyone builds childcare apps for *operators* (management tools: billing, attendance, parent comms). Nobody has built the discovery layer for *parents*. Portugal's Carta Social has the authoritative data; nobody has made it usable. This project has the data, the geocoding, and the domain knowledge to be the first.

The "whoa" moment: a parent in Alvalade types their postcode and sees 47 pins — green IPSS, orange private, blue public — within 2km. They've never seen this before. They didn't know there were 47 options.

## Agreed Premises

1. Parents' primary pain is **discovery** — finding options before evaluating them.
2. "Definitive" means showing **depth**: capacity, IPSS vs private vs public, cost band — not just pins.
3. **Search-first, map as context** — parent enters a location/postcode → gets a list of results with a map panel supporting spatially. The map is a visual aid, not the primary interaction.
4. **Mobile-first** — the pão-de-forma parent is on their phone.

## Approaches Considered

### Approach A: Next.js + Mapbox (Chosen)
- **Stack:** Next.js 14 (App Router), Mapbox GL JS, Supabase JS client + PostGIS, Vercel
- **Effort:** ~€0/month, ~2h with Claude Code
- **Why:** SSR is essential for SEO — "creche alvalade" should rank; PostGIS radius queries are the right tool for geo search; Mapbox free tier covers early traffic
- **Completeness:** 9/10

### Approach B: SvelteKit + Leaflet
- Lighter bundle, free tiles, faster to prototype
- Weaker SSR/SEO story; smaller ecosystem
- **Completeness:** 7/10

### Approach C: Static HTML + Mapbox
- Fastest to ship; no framework
- No SSR = bad for local search SEO — kills the long-term strategy
- **Completeness:** 5/10

### Supabase Schema (proposed)

```sql
CREATE TABLE instituicoes (
  id              TEXT PRIMARY KEY,         -- from Carta Social
  slug            TEXT UNIQUE,              -- generated on import: id + slugified nome
  nome            TEXT NOT NULL,
  nome_google     TEXT,
  tipo            TEXT,                     -- 'Creche', 'Jardim de Infância', etc.
  natureza_juridica TEXT,                   -- 'IPSS', 'Privado', 'Público'
  morada          TEXT,
  codigo_postal   TEXT,
  localidade      TEXT,
  freguesia       TEXT,
  concelho        TEXT,
  distrito        TEXT,
  telefone        TEXT,
  telefone_google TEXT,
  email           TEXT,
  website_google  TEXT,
  capacidade      INTEGER,
  utentes         INTEGER,
  horario         TEXT,
  ultima_atualizacao DATE,
  location        GEOGRAPHY(POINT, 4326),   -- PostGIS
  search_vector   TSVECTOR                  -- full-text search
);

-- Spatial index
CREATE INDEX idx_location ON instituicoes USING GIST(location);

-- Full-text search index
CREATE INDEX idx_search ON instituicoes USING GIN(search_vector);

-- Populate search_vector on insert/update
CREATE TRIGGER tsvector_update BEFORE INSERT OR UPDATE ON instituicoes
  FOR EACH ROW EXECUTE FUNCTION
  tsvector_update_trigger(search_vector, 'pg_catalog.portuguese', nome, localidade, concelho);

-- PostGIS radius search RPC (SECURITY DEFINER so anon key can call it)
-- radius_m capped at 50km to prevent full-table scans; page_offset increments by 50
CREATE FUNCTION nearby_instituicoes(lat FLOAT, lng FLOAT, radius_m INT, page_offset INT DEFAULT 0)
RETURNS SETOF instituicoes AS $$
  SELECT * FROM instituicoes
  WHERE ST_DWithin(
    location,
    ST_MakePoint(lng, lat)::geography,
    LEAST(radius_m, 50000)   -- guard: max 50km
  )
  ORDER BY ST_Distance(location, ST_MakePoint(lng, lat)::geography)
  LIMIT 50 OFFSET page_offset;
$$ LANGUAGE sql SECURITY DEFINER;

-- RLS: all rows readable by anon (directory is public)
ALTER TABLE instituicoes ENABLE ROW LEVEL SECURITY;
CREATE POLICY "public read" ON instituicoes FOR SELECT USING (true);
```

### Colour System — by `natureza_juridica` (NOT `tipo`)

### Key Interactions

1. **Home:** Search box, debounced autocomplete queries `localidade` and `concelho` columns in Supabase (ILIKE `%q%`, returns distinct values). Postcode input is a **separate code path** — detect `XXXX-XXX` pattern, look up lat/lng from a **static postcode table** in Supabase (do not call Nominatim at runtime; import CTT postcode data once). Postcode → coords → pass to `nearby_instituicoes`.

2. **Results (`/search?q=alvalade&r=2000&tipo=`):**
   - Search params are URL query strings — search is shareable and bookmarkable.
   - List (left, scrollable) + Map (right, sticky). Cards show: nome, badge (`natureza_juridica`), address, distance, capacidade.
   - **Bidirectional sync:** shared `activeId` state. Clicking a card: set `activeId`, map flyTo pin. Clicking a pin: set `activeId`, list scrolls to card via `scrollIntoView`.
   - **Pagination:** 50 results per page, "Load more" button increments `page_offset` in RPC.
   - **Empty state:** "Nenhuma creche encontrada num raio de Xkm. Tente alargar o raio." + button to double radius.
   - **No-coordinates fallback:** rows without `location` are returned by a separate list-only query (no radius filter) and shown in a "Sem localização exacta" section below the map results.

3. **Detail page (`/creche/[id]-[slug]`):**
   - Slug format: `[id]-[nome-slugified]` e.g. `1234-creche-da-paroquia-de-alvalade`. Decided — use this format. Slugify on import.
   - Static map image (Mapbox Static Images API, not GL — saves map load quota) on detail page.
   - Shows `ultima_atualizacao` as "Dados actualizados em [date]" — transparency signal.

4. **Filters (v1):** `natureza_juridica` (IPSS / Privado / Público), radius (500m / 1km / 2km / 5km)
